# แผนพัฒนา LINE Controller Bot

> สถานะ: แผนงาน v4 — เริ่ม Phase 1 แล้ว (29 ก.ย. 2026)
> ข้อความที่บอทใช้: [MESSAGES.md](MESSAGES.md) · วิธีติดตั้งและทดลอง: [SETUP.md](SETUP.md)

## 1. โจทย์และสิ่งที่ตกลงแล้ว

- เราเป็น **โรงงานลูกชิ้น** ลูกค้าเป้าหมายส่วนใหญ่คือ **ร้านก๋วยเตี๋ยวเปิดใหม่**
- รายชื่อร้านใหม่มาจากการสแกน Google Maps **เดือนละ 1 รอบ** เก็บในตาราง `"Shop"` บน **Neon** หาเจอเท่าไรทักทั้งหมด
- ทักด้วย **บัญชี LINE ใหม่ที่ตั้งชื่อแยก** (ไม่ใช่ชื่อจริงพนักงาน) บนมือถือ **Honor 400 Pro**
  คอมพิวเตอร์ที่ต่อมือถือตอนนี้เป็น PC ภายหลังย้ายไป MacBook
- ข้อความแรกใช้แบบ **Q2**: "สวัสดีครับ ร้าน… เปิดขายอยู่ไหมครับ 🙏"

สิ่งที่บอทต้องทำ:

1. ค้นเบอร์ → เพิ่มเพื่อน → ส่งคำถามเปิดบทสนทนา
2. บันทึกว่าร้านไหนตอบแล้ว และร้านเปิดแล้ว / ยังไม่เปิด / ปิดกิจการ
3. ตอบกลับอัตโนมัติ 1 ครั้ง (แนะนำตัว + ข้อเสนอ) แล้วส่งต่อให้พนักงานคุยเอง

> LINE OA ใช้ทักครั้งแรกไม่ได้ เพราะ OA ค้นหาหรือเพิ่มเพื่อนจากเบอร์โทรไม่ได้ จึงเป็นทางเลือกในเฟสหลัง (ข้อ 8)

## 2. ข้อจำกัดของ LINE

| เรื่อง | รายละเอียด | ผลต่อการออกแบบ |
|---|---|---|
| ร้านต้องเปิด "ให้ผู้อื่นเพิ่มเพื่อน" | ค้นหาด้วยเบอร์จะเจอเฉพาะคนที่เปิดการตั้งค่านี้ | มีสถานะ `NOT_FOUND`; ร้านที่ค้นไม่เจอให้พนักงานโทรหรือส่ง SMS แทน |
| LINE จำกัดการค้นหา | ค้นเกินจำนวน หรือค้นไม่เจอติดกันหลายครั้ง → ระงับการค้นหาชั่วคราว (ไม่เปิดเผยตัวเลข) | โควตาต่อวัน, คัดเบอร์บ้าน/เบอร์เสียทิ้งก่อนค้น, พักเครื่องเมื่อค้นไม่เจอติดกัน, หยุดทันทีเมื่อมีข้อความเตือน |
| เพื่อนสูงสุด 5,000 คนต่อบัญชี | นับรวมคนที่ซ่อน/บล็อก | ถ้าเพิ่มเดือนละ 300 ร้าน จะเต็มในราว 1 ปีครึ่ง — วางแผนบัญชีที่ 2 หรือ LINE OA ก่อนถึงเพดาน |
| เงื่อนไขการใช้งาน LINE | บัญชีปกติไม่ได้มีไว้ทักคนจำนวนมาก และ LINE ไม่รองรับการควบคุมแอปด้วยโปรแกรม → อาจถูกจำกัด/ระงับ | ปริมาณต่ำ, ข้อความสุภาพ, ไม่ทักซ้ำ, ข้อมูลร้านเก็บใน Neon ไม่ผูกกับบัญชี |
| PDPA | เบอร์ร้านมักเป็นเบอร์ส่วนตัวของเจ้าของร้าน | ถ้าร้านถามที่มาของเบอร์ต้องบอกได้ (Google Maps), มีรายชื่อห้ามติดต่อ |
| UI ของ LINE เปลี่ยนตามเวอร์ชัน | บอทที่อิงหน้าจออาจพังเมื่อ LINE อัปเดต | ปิด auto-update, เก็บ selector ใน `config/selectors.yaml`, เก็บภาพหน้าจอทุกครั้งที่ error |

## 3. ภาพรวมระบบ

```text
Neon (PostgreSQL)
 ├─ public."Shop"       ตารางเดิมจากการสแกน Google Maps — บอทอ่านอย่างเดียว
 └─ line_bot.*          ตารางของบอท (outreach, messages, devices)
      ▲
      │
 Bot (Python บนคอมพิวเตอร์ที่ต่อมือถือ)
 ├─ import      ดึงร้านใหม่จาก "Shop" เข้าคิว
 ├─ worker      USB/ADB + uiautomator2 → Honor 400 Pro → LINE
 │                ค้นเบอร์ → เพิ่มเพื่อน → เปลี่ยนชื่อเป็นรหัสร้าน → ถามว่าร้านเปิดไหม
 │                → อ่านคำตอบ → ตอบอัตโนมัติ 1 ครั้ง → แจ้งพนักงาน (Telegram)
 └─ dashboard   ร้านที่ตอบแล้ว, พนักงานอัปเดตผล/นัดทักใหม่, funnel รายเดือน
```

พนักงานคุยต่อผ่าน **LINE PC ที่ล็อกอินบัญชีเดียวกัน** (มือถือเครื่องบอทห้ามคนใช้ระหว่างบอททำงาน)

### เครื่องมือ

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| ภาษา | Python 3.11+ | รันได้ทั้ง Windows และ macOS |
| ควบคุมมือถือ | [uiautomator2](https://github.com/openatx/uiautomator2) (ทำงานบน ADB) | หาปุ่มจาก resource-id/ข้อความ, ใส่ข้อความภาษาไทยได้ (`adb shell input text` พิมพ์ไทยไม่ได้) |
| ดูหน้าจอสด | scrcpy | เฝ้าดูมือถือจากคอมพิวเตอร์ |
| ฐานข้อมูล | Neon + psycopg 3 | ใช้ฐานข้อมูลเดิม |
| Dashboard | Streamlit | ทำได้เร็ว พนักงานกดอัปเดตผลได้ |
| แจ้งเตือนพนักงาน | Telegram (ฟรี) | LINE Notify ปิดบริการไปแล้วเมื่อ 31 มี.ค. 2025 |

## 4. ขั้นตอนการทำงาน

### 4.1 นำเข้ารอบเดือน (`python -m bot import`) — เสร็จแล้ว

1. อ่านร้านจาก `"Shop"` ที่ยังไม่อยู่ใน `line_bot.outreach` ตามตัวกรองใน `config/settings.yaml`:
   `"status"` = `none`, `"visited"` = false, และเลือกกรอง `"foodType"` / `"calculatedAgeDays"` ได้
2. Normalize `"phoneNumber"` (ตัดช่องว่าง/ขีด, `+66` → `0`, เลขไทย → เลขอารบิก, เอาเบอร์แรกถ้ามีหลายเบอร์)
   เก็บเฉพาะมือถือ 10 หลัก (`06`/`08`/`09`) — เบอร์บ้าน, เบอร์ผิดรูปแบบ, ไม่มีเบอร์, เบอร์ซ้ำ → `INVALID` พร้อมเหตุผล
3. เรียงคิวตาม `"calculatedAgeDays"` น้อยสุดก่อน (ร้านเปิดใหม่ล่าสุดได้ทักก่อน)
4. ทุกร้านได้รหัส `C` + เลขลำดับ (เช่น `C1023`) ใช้ตั้งชื่อเพื่อนใน LINE
5. รันครั้งแรกแสดงตัวอย่างเท่านั้น ต้องใส่ `--commit` จึงบันทึกจริง; รันซ้ำได้ ร้านที่นำเข้าแล้วจะไม่ถูกนำเข้าอีก

ระยะเวลาทักทั้งรอบ ≈ จำนวนร้านที่พร้อมทัก ÷ โควตาต่อวัน เช่น โควตา 15 ร้าน/วัน: 300 ร้าน ≈ 20 วัน

### 4.2 ทักครั้งแรก (ต่อ 1 ร้าน)

1. กลับหน้าหลักของ LINE
2. เพิ่มเพื่อน → ค้นหา → หมายเลขโทรศัพท์ → ใส่เบอร์ → ค้นหา
3. อ่านผลลัพธ์: เจอ → กดเพิ่ม / เป็นเพื่อนแล้ว → ข้ามไปขั้นทัก / ไม่พบ → `NOT_FOUND` /
   ถูกจำกัดการค้นหา → พักเครื่องถึงวันถัดไป + แจ้งเตือน (ร้านนี้กลับเป็น `PENDING`)
4. เปลี่ยนชื่อที่แสดงของเพื่อนเป็น `C1023 ชื่อร้าน` (เห็นเฉพาะฝั่งเรา) — ใช้จับคู่การแจ้งเตือน/แชทกับร้าน
5. ส่งข้อความ Q2 → ตรวจว่าข้อความออกไปจริง → `MESSAGED`
6. บันทึกทุกขั้นลง Neon ทันที (บอทล่มแล้วทำต่อได้ ไม่ทักซ้ำ) และเว้นระยะสุ่ม 1–3 นาทีก่อนร้านถัดไป
7. ทักร้านใหม่ช่วง 14:00–16:30 (เลี่ยงช่วงร้านยุ่งตอนเที่ยงและเย็น)

ข้อ 1–5 ทดลองได้แล้วกับเบอร์ทีมผ่าน `python -m bot poc` (หลังเติม selector จากมือถือจริง)

### 4.3 ตรวจคำตอบ

| ชั้น | วิธี | ความถี่ |
|---|---|---|
| 1. Notification | อ่านการแจ้งเตือนของ LINE (ชื่อที่มีรหัสร้าน + ข้อความ) ผ่าน `adb shell dumpsys notification --noredact` | ทันทีที่มีข้อความ |
| 2. สแกนรายการแชท | เปิดแท็บแชท อ่านชื่อ + ตัวเลขยังไม่อ่าน โดยไม่กดเข้าห้อง — เก็บตกตอนการแจ้งเตือนไม่เด้ง | ทุก 15–30 นาที |
| 3. อ่านในห้องแชท | ก่อนตอบ อ่านข้อความเต็มของร้าน (การแจ้งเตือนอาจตัดข้อความ) | ทุกครั้งที่ตอบ |

### 4.4 ตอบอัตโนมัติ 1 ครั้ง แล้วส่งต่อพนักงาน

ตัวจัดกลุ่มคำตอบเสร็จแล้ว (`bot/classifier.py` + `config/reply_rules.yaml`):

| คำตอบของร้าน | บอทตอบ | สถานะ |
|---|---|---|
| ไม่พอใจ / ถามที่มาของเบอร์ | B4 ขออภัย + บอกที่มา | `DECLINED` + ห้ามติดต่อ + แจ้งเตือน |
| ทักผิดเบอร์ | B6 ขออภัย | `DECLINED` + ห้ามติดต่อ |
| ปฏิเสธ | B5 ขอบคุณ | `DECLINED` + ห้ามติดต่อ |
| ปิดกิจการแล้ว | B3 ขอบคุณที่แจ้ง | `CLOSED` + ห้ามติดต่อ |
| ยังไม่เปิดร้าน | B2 แนะนำตัว + ชวนลองตัวอย่างก่อนเปิดร้าน | `PITCHED` (ร้าน: ยังไม่เปิด) |
| อื่น ๆ (เปิดแล้ว, ใช่, มีอะไรครับ, สติกเกอร์) | B1 แนะนำตัว + ข้อเสนอ | `PITCHED` |

- หลังบอทตอบแล้ว ข้อความใหม่จากร้าน → แจ้งพนักงาน (`needs_human`) ยกเว้นร้านปฏิเสธชัดเจน บอทปิดบทสนทนาให้ได้
- `auto_pitch` ปิดไว้ก่อน จนกว่าจะแก้ชนิดลูกชิ้นและข้อเสนอใน B1/B2 ให้ตรงของจริง — ระหว่างนี้บอทแค่บันทึกและแจ้งพนักงาน
- ร้านไม่ตอบภายใน 7 วัน → `NO_REPLY` (ไม่ทักซ้ำ)

### 4.5 Dashboard และพนักงาน

- แจ้งเตือนเข้ากลุ่ม Telegram: ชื่อร้าน, รหัส, ข้อความของร้าน
- พนักงานตอบผ่าน LINE PC และบันทึกผลใน dashboard: สนใจ / ไม่สนใจ / ยังไม่เปิด (นัดวันทักใหม่) / เป็นลูกค้า
- Funnel ต่อรอบสแกน: รายชื่อ → มีเบอร์มือถือ → เพิ่มเพื่อนได้ → ทักแล้ว → ตอบ → สนใจ → เป็นลูกค้า

### 4.6 ความปลอดภัยของบัญชีและความทนทาน

- โควตาเริ่มต่ำ (10–20 ร้าน/วัน) แล้วค่อยปรับ, เว้นระยะแบบสุ่ม, ค้นไม่เจอติดกัน 5 ครั้ง → พัก 1 ชั่วโมง
- เจอข้อความเตือนหรือถูกจำกัด → หยุดเครื่องทันที + แจ้งเตือน
- error → เก็บภาพหน้าจอ + โครงสร้างหน้าจอไว้ใน `logs/`; กู้คืนโดยกด Back จนถึงหน้าหลัก ไม่ได้ก็ปิดแล้วเปิด LINE ใหม่

## 5. ฐานข้อมูล

- ตารางของบอทอยู่ใน schema **`line_bot`** แยกจาก `public` เพื่อไม่ให้ปนกับตารางเดิม
  และเครื่องมือจัดการ schema ของระบบเดิม (เช่น Prisma/Drizzle ที่ดูแลเฉพาะ `public`) จะไม่มองเห็นหรือพยายามลบ
- บอท **อ่าน `"Shop"` อย่างเดียว** ไม่แก้ `"status"` หรือคอลัมน์อื่น และไม่ใส่ foreign key ไปที่ `"Shop"`
- โครงตารางเต็มอยู่ใน [`db/schema.sql`](../db/schema.sql) (รันซ้ำได้):

| ตาราง | เก็บอะไร | คอลัมน์หลัก |
|---|---|---|
| `line_bot.outreach` | สถานะการทักของแต่ละร้าน (1 ร้าน / 1 เบอร์ ทักครั้งเดียว) | `code`, `place_id`, `phone`, `status`, `shop_state`, `reply_group`, `needs_human`, `do_not_contact`, เวลาของแต่ละขั้น |
| `line_bot.messages` | ประวัติข้อความเข้า/ออก | `outreach_id`, `direction`, `sender`, `text`, `source` |
| `line_bot.devices` | มือถือ/บัญชีที่บอทใช้ | `device_id`, `daily_quota`, `status`, `paused_until` |

- Neon หยุด compute เมื่อว่าง 5 นาที การเชื่อมต่อแรกหลังจากนั้นช้าขึ้นเล็กน้อย บอทจึงลองเชื่อมต่อซ้ำให้อัตโนมัติ
- connection string เก็บในไฟล์ `.env` (ไม่ขึ้น GitHub) และแนะนำให้ทดสอบบน branch `dev` ของ Neon ก่อน

## 8. คำถามที่ยังเปิดอยู่

- ชื่อโรงงาน ชื่อในบัญชี LINE ชนิดลูกชิ้น และข้อเสนอจริง — ต้องมีก่อนเปิด `auto_pitch` (Q2 ไม่ต้องใช้)
- `"Shop"."status"` มีค่าอะไรบ้าง และอยากให้บอทอัปเดตค่านี้ด้วยไหม (ตอนนี้บอทไม่แตะ)
- ร้านที่ `"visited"` = true ควรข้ามไหม (ตอนนี้ข้าม)
