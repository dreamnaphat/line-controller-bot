# แผนพัฒนา LINE Controller Bot

> สถานะ: แผนงาน v3 — ใช้ LINE ของพนักงานทักด้วยคำถามสั้น ๆ (29 ก.ย. 2026) ยังไม่เริ่มเขียนโค้ด
> ข้อความทั้งหมดที่บอทใช้อยู่ใน [MESSAGES.md](MESSAGES.md)

## 1. โจทย์

- เราเป็น **โรงงานลูกชิ้น** ลูกค้าเป้าหมายส่วนใหญ่คือ **ร้านก๋วยเตี๋ยวเปิดใหม่**
- หารายชื่อร้านใหม่ **เดือนละ 1 รอบ** หาเจอเท่าไรทักทั้งหมด เบอร์ร้านเก็บอยู่ใน **Neon** (PostgreSQL)
- ทักด้วย **LINE ของพนักงาน** ข้อความแรกเป็นคำถามสั้น ๆ ว่า "ร้านเปิดขายแล้วใช่ไหม"

สิ่งที่บอทต้องทำ:

1. ค้นเบอร์ → เพิ่มเพื่อน → ส่งคำถามเปิดบทสนทนา
2. บันทึกว่าร้านไหนตอบแล้ว และร้านเปิดแล้ว / ยังไม่เปิด / ปิดกิจการ
3. ตอบกลับอัตโนมัติ 1 ครั้ง (แนะนำตัว + ข้อเสนอ) แล้วส่งต่อให้พนักงานคุยเอง

> LINE OA ใช้ทักครั้งแรกไม่ได้ เพราะ OA ค้นหาหรือเพิ่มเพื่อนจากเบอร์โทรไม่ได้ ต้องให้ลูกค้าเป็นฝ่ายเพิ่มเพื่อนหรือทักเข้ามาก่อน
> OA จึงย้ายไปเป็นทางเลือกในเฟสหลัง (ข้อ 9)

## 2. บัญชีที่ใช้ทัก

| | บัญชีใหม่ในชื่อพนักงาน (แนะนำ) | LINE ส่วนตัวจริงของพนักงาน |
|---|---|---|
| สิ่งที่ร้านเห็น | ชื่อและรูปของพนักงาน | ชื่อและรูปของพนักงาน |
| ถ้าบัญชีถูกจำกัด/ระงับ | เสียแค่บัญชีงาน | พนักงานเสีย LINE ส่วนตัว (แชท เพื่อน กลุ่มครอบครัว) |
| ความเป็นส่วนตัว | บอทเห็นเฉพาะแชทงาน | บอทเห็น notification และรายการแชทส่วนตัวของพนักงานด้วย |
| มือถือ | เครื่องของบริษัท เสียบ PC ไว้ได้ทั้งวัน | ต้องใช้มือถือของพนักงาน (1 บัญชี LINE ใช้บนมือถือได้ครั้งละเครื่อง) เสียบ PC และห้ามใช้ระหว่างบอททำงาน |
| ต้องมี | ซิม 1 เบอร์ที่ยังไม่ผูกกับ LINE ของใคร | ความยินยอมของพนักงาน |

ถ้าเลือกใช้ LINE ส่วนตัวจริง ต้องมีข้อป้องกันเพิ่ม:

- บอทอ่านและบันทึกเฉพาะแชทที่ชื่อขึ้นต้นด้วยรหัสร้าน (เช่น `C1023`) ข้อความอื่นทิ้งทันที ไม่เก็บลงฐานข้อมูลหรือ log
- บอทไม่เปิดแชทอื่นนอกจากแชทร้าน
- พนักงานยินยอมเป็นลายลักษณ์อักษร และรู้ว่าบัญชีอาจถูกจำกัด
- บอทรันเฉพาะช่วงเวลาที่ตกลงกัน

## 3. ข้อจำกัดของ LINE

| เรื่อง | รายละเอียด | ผลต่อการออกแบบ |
|---|---|---|
| ร้านต้องเปิด "ให้ผู้อื่นเพิ่มเพื่อน" | ค้นหาด้วยเบอร์จะเจอเฉพาะคนที่เปิดการตั้งค่านี้ | มีสถานะ `NOT_FOUND`; ร้านที่ค้นไม่เจอให้พนักงานโทรหรือส่ง SMS แทน |
| LINE จำกัดการค้นหา | ค้นเกินจำนวน หรือค้นไม่เจอติดกันหลายครั้ง → ระงับการค้นหาชั่วคราว (ไม่เปิดเผยตัวเลข) | โควตาต่อวัน, คัดเบอร์เสียทิ้งก่อน, พักเครื่องเมื่อค้นไม่เจอติดกัน, หยุดทันทีเมื่อมีข้อความเตือน |
| เพื่อนสูงสุด 5,000 คนต่อบัญชี | นับรวมคนที่ซ่อน/บล็อก | ประมาณ 1 ปีครึ่งถ้าเพิ่มเดือนละ 300 ร้าน — วางแผนบัญชีที่ 2 หรือ LINE OA ก่อนถึงเพดาน |
| เงื่อนไขการใช้งาน LINE | บัญชีปกติไม่ได้มีไว้ทักคนจำนวนมาก และ LINE ไม่รองรับการควบคุมแอปด้วยโปรแกรม → อาจถูกจำกัด/ระงับ | ปริมาณต่ำ, ข้อความสุภาพ, ไม่ทักซ้ำ, ข้อมูลลูกค้าเก็บใน Neon ไม่ผูกกับบัญชี |
| PDPA | เบอร์ร้านมักเป็นเบอร์ส่วนตัวของเจ้าของร้าน | ถ้าร้านถามที่มาของเบอร์ต้องบอกได้, มีรายชื่อห้ามติดต่อ |
| UI ของ LINE เปลี่ยนตามเวอร์ชัน | บอทที่อิงหน้าจออาจพังเมื่อ LINE อัปเดต | ปิด auto-update, เก็บ selector ในไฟล์ config, เก็บ screenshot ทุกครั้งที่ error |

## 4. ภาพรวมระบบ

```text
Neon (PostgreSQL) — สถานะของทุกร้านอยู่ที่นี่ที่เดียว
 ├─ Phone bot (Python บน PC ที่ต่อมือถือ)
 │    └─ USB/ADB + uiautomator2 → Android → LINE ของพนักงาน
 │         ค้นเบอร์ → เพิ่มเพื่อน → เปลี่ยนชื่อเป็นรหัสร้าน → ถามว่าร้านเปิดไหม
 │         → อ่านคำตอบ → ตอบอัตโนมัติ 1 ครั้ง → แจ้งพนักงาน
 ├─ แจ้งเตือนพนักงาน (Telegram)
 └─ Dashboard (เว็บ)
      ร้านที่ตอบแล้ว, พนักงานอัปเดตผล/นัดทักใหม่, funnel รายเดือน
```

พนักงานคุยต่อผ่าน **LINE PC ที่ล็อกอินบัญชีเดียวกัน** (หรือบนมือถือนอกเวลาที่บอททำงาน)

### เครื่องมือ

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| ภาษา | Python 3.11+ | ไลบรารีควบคุม Android และจัดการข้อมูลครบ |
| ควบคุมมือถือ | [uiautomator2](https://github.com/openatx/uiautomator2) (ทำงานบน ADB) | หาปุ่มจาก resource-id/ข้อความ, ใส่ข้อความภาษาไทยได้, มี watcher ปิด popup |
| หา selector | uiautodev | ดูโครงสร้างหน้าจอ LINE |
| ดูหน้าจอสด | scrcpy | เฝ้าดูมือถือจาก PC |
| ฐานข้อมูล | Neon + SQLAlchemy/psycopg | ใช้ฐานข้อมูลเดิม |
| Dashboard | Streamlit | ทำได้เร็ว พนักงานกดอัปเดตผลได้ |
| แจ้งเตือนพนักงาน | Telegram (ฟรี) | LINE Notify ปิดบริการไปแล้วเมื่อ 31 มี.ค. 2025 |

> ห้ามใช้ `adb shell input text` ส่งข้อความ เพราะพิมพ์ภาษาไทยไม่ได้ — ใช้ `set_text()` ของ uiautomator2 (สำรอง: ADBKeyBoard)

## 5. ขั้นตอนการทำงาน

### 5.1 นำเข้ารอบเดือน

1. เมื่อรายชื่อร้านใหม่ของเดือนเข้า Neon แล้ว → สคริปต์สร้างแถว `line_outreach` สถานะ `PENDING` ให้ทุกร้านที่ยังไม่เคยทัก
2. Normalize เบอร์ (ตัด `-`/ช่องว่าง, `+66` → `0`) เก็บเฉพาะมือถือ 10 หลัก (`06`/`08`/`09`) ที่เหลือเป็น `INVALID`
3. เบอร์ที่เคยทักแล้วในเดือนก่อน ๆ หรืออยู่ในรายชื่อห้ามติดต่อ → ข้าม
4. สร้างรหัสประจำร้าน เช่น `C1023`
5. เรียงคิวให้ร้านที่เพิ่งเปิดล่าสุดได้ก่อน

ระยะเวลาทั้งรอบ ≈ จำนวนร้าน ÷ โควตาต่อวัน เช่น โควตา 15 ร้าน/วัน: 100 ร้าน ≈ 7 วัน, 300 ร้าน ≈ 20 วัน

### 5.2 ทักครั้งแรก (ต่อ 1 ร้าน)

1. กลับหน้า Home ของ LINE
2. เพิ่มเพื่อน → ค้นหา → หมายเลขโทรศัพท์ → ใส่เบอร์ → ค้นหา
3. อ่านผลลัพธ์:
   - พบ → กดเพิ่ม → `ADDED`
   - เป็นเพื่อนอยู่แล้ว → ข้ามไปขั้นทัก
   - ไม่พบ → `NOT_FOUND`
   - ถูกจำกัดการค้นหา → พักเครื่องถึงวันถัดไป + แจ้งเตือน (ร้านนี้กลับเป็น `PENDING`)
4. เปลี่ยนชื่อที่แสดงของเพื่อนเป็น `C1023 ชื่อร้าน` (เห็นเฉพาะฝั่งเรา) — ใช้จับคู่ notification/แชทกับร้านได้แน่นอน
5. ส่งคำถามเปิดบทสนทนา ([MESSAGES.md](MESSAGES.md) ข้อ Q1 หรือ Q2) → ตรวจว่าข้อความขึ้นจริง → `MESSAGED`
6. บันทึกทุกขั้นลง Neon ทันที (บอทล่มแล้วทำต่อได้ ไม่ทักซ้ำ) และเว้นระยะสุ่ม 1–3 นาทีก่อนร้านถัดไป
7. ช่วงเวลาทักร้านใหม่: 14:00–16:30 (เลี่ยงช่วงร้านยุ่งตอนเที่ยงและเย็น)

### 5.3 ตรวจคำตอบ

| ชั้น | วิธี | ความถี่ |
|---|---|---|
| 1. Notification | อ่านการแจ้งเตือนของ LINE (ชื่อที่มีรหัสร้าน + ข้อความ) ผ่าน `adb shell dumpsys notification --noredact` | ทันทีที่มีข้อความ |
| 2. สแกนรายการแชท | เปิดแท็บแชท อ่านชื่อ + ตัวเลขยังไม่อ่าน โดยไม่กดเข้าห้อง — เก็บตกตอน notification ไม่เด้ง | ทุก 15–30 นาที |
| 3. อ่านในห้องแชท | ก่อนตอบ บอทอ่านข้อความเต็มของร้านในห้องแชท (notification อาจตัดข้อความ) | ทุกครั้งที่ตอบ |

ทุกคำตอบที่จับได้ → บันทึกลง `line_messages`, อัปเดต `first_reply_at` / `last_reply_text` และสถานะ `REPLIED`
(ถ้าพนักงานเปิดอ่านจาก LINE PC ก่อน ตัวเลขยังไม่อ่านจะหาย จึงต้องพึ่ง notification เป็นหลัก)

### 5.4 ตอบอัตโนมัติ 1 ครั้ง แล้วส่งต่อพนักงาน

บอทจัดกลุ่มคำตอบของร้านตามกฎใน [MESSAGES.md](MESSAGES.md) ส่วน D แล้วตอบ 1 ครั้ง:

| คำตอบของร้าน | บอทตอบ | สถานะ |
|---|---|---|
| ไม่พอใจ / ถามที่มาของเบอร์ | B4 ขออภัย + บอกที่มา | `DECLINED` + ห้ามติดต่อ + แจ้งเตือน |
| ปฏิเสธ | B5 ขอบคุณ | `DECLINED` + ห้ามติดต่อ |
| ปิดกิจการแล้ว | B3 ขอบคุณที่แจ้ง | `CLOSED` + ห้ามติดต่อ |
| ยังไม่เปิดร้าน | B2 แนะนำตัว + ชวนลองตัวอย่างก่อนเปิดร้าน | `PITCHED` (ร้าน: ยังไม่เปิด) |
| อื่น ๆ (เปิดแล้ว, ใช่, มีอะไรครับ, ใครครับ, สติกเกอร์) | B1 แนะนำตัว + ข้อเสนอ | `PITCHED` |

- หลังบอทตอบแล้ว ข้อความใหม่จากร้าน → แจ้งเตือนพนักงาน (`needs_human`) บอทไม่ตอบเองอีก
  ยกเว้นร้านปฏิเสธหรือไม่พอใจชัดเจน บอทปิดบทสนทนาอย่างสุภาพให้ได้ทุกช่วง
- เปิด/ปิดการตอบอัตโนมัติได้ใน `config/settings.yaml` (`auto_pitch`) — ถ้าปิด บอทแค่บันทึกและแจ้งพนักงาน
- ตอบเฉพาะในเวลาทำการ
- ไม่ตอบภายใน 7 วัน → `NO_REPLY` (ค่าเริ่มต้นไม่ทักซ้ำ เพื่อลดความเสี่ยงของบัญชีพนักงาน)

### 5.5 พนักงานคุยต่อ

- แจ้งเตือนเข้ากลุ่ม Telegram: ชื่อร้าน, รหัส, ข้อความของร้าน, ลิงก์ไปหน้า dashboard
- พนักงานตอบผ่าน LINE PC (บัญชีเดียวกัน) — ห้ามใช้มือถือเครื่องบอทระหว่างบอททำงาน
- พนักงานบันทึกผลใน dashboard: สนใจ / ไม่สนใจ / ยังไม่เปิด (นัดวันทักใหม่) / เป็นลูกค้า + โน้ต
- ข้อความสำเร็จรูปสำหรับพนักงานอยู่ใน [MESSAGES.md](MESSAGES.md) ส่วน C

### 5.6 Dashboard

- Funnel ต่อรอบเดือน: รายชื่อ → เพิ่มเพื่อนได้ → ทักแล้ว → ตอบ → สนใจ → เป็นลูกค้า
- สัดส่วนร้านที่เปิดแล้ว / ยังไม่เปิด / ปิดกิจการ
- เทียบอัตราการตอบของข้อความแรกแบบ Q1 และ Q2
- รายการที่รอพนักงาน (`needs_human`) และร้านที่ถึงวันนัดทักใหม่
- สถานะเครื่องและโควตาวันนี้, export CSV

### 5.7 ความปลอดภัยของบัญชีและความทนทาน

- โควตาเริ่มต่ำ (10–20 ร้าน/วัน) แล้วค่อยปรับจากผลจริง, เว้นระยะแบบสุ่ม
- ค้นไม่เจอติดกันหลายครั้ง (ค่าเริ่มต้น 5) → พักเครื่อง 1 ชั่วโมง
- เจอ popup เตือนหรือถูกจำกัด → หยุดเครื่องทันที + แจ้งเตือน
- selector อยู่ใน `config/selectors.yaml`; ลำดับการหา: resource-id → ข้อความ → รูปภาพ/OCR
- error → เก็บ screenshot + UI dump + log; recovery: กด Back จนถึง Home → force-stop แล้วเปิด LINE ใหม่
- health check ก่อนเริ่มงาน: ADB เชื่อมต่อ, จอติด, LINE ล็อกอินอยู่, แบตเตอรี่พอ

## 6. Neon

- Neon คือ PostgreSQL ใช้ schema ในข้อ 7 ได้ทันที — สร้างตารางโดยวาง SQL ใน SQL Editor ของ Neon Console
- Neon หยุด compute เมื่อว่าง 5 นาที (แพ็กเกจ Free/Launch) การเชื่อมต่อแรกหลังจากนั้นจะช้าขึ้นครึ่งวินาทีถึงไม่กี่วินาที → เปิด `pool_pre_ping` และ retry
- Dashboard ที่รันบนคลาวด์ให้ใช้ connection string แบบ pooled (hostname มี `-pooler` และต่อท้าย `sslmode=require`)
- สร้าง branch `dev` ใน Neon ไว้ทดสอบ ไม่แตะข้อมูลจริง
- เก็บ connection string ในตัวแปร `DATABASE_URL` (ไฟล์ `.env` ที่ไม่ commit) — ห้ามใส่ในโค้ดหรือส่งในแชท

## 7. ฐานข้อมูล (ตารางใหม่ใน Neon)

```sql
-- สถานะการทักของแต่ละเบอร์ (1 เบอร์ ทักครั้งเดียว)
CREATE TABLE line_outreach (
    id               BIGSERIAL    PRIMARY KEY,
    prospect_id      BIGINT       NOT NULL,           -- id ในตารางร้านค้าเดิม
    batch_month      DATE         NOT NULL,           -- รอบเดือน เช่น 2026-10-01
    phone            VARCHAR(15)  NOT NULL UNIQUE,    -- normalize แล้ว เช่น 0812345678
    code             VARCHAR(12)  NOT NULL UNIQUE,    -- เช่น C1023 (ใช้เปลี่ยนชื่อเพื่อน)
    device_id        VARCHAR(64),                     -- เครื่อง/บัญชีที่ทัก
    line_name        VARCHAR(100),                    -- ชื่อโปรไฟล์ LINE ตอนค้นเจอ
    opener_variant   VARCHAR(8),                      -- ข้อความแรกแบบ Q1 หรือ Q2
    status           VARCHAR(20)  NOT NULL DEFAULT 'PENDING',
    shop_state       VARCHAR(12),                     -- OPEN | NOT_OPEN_YET | CLOSED | UNKNOWN
    needs_human      BOOLEAN      NOT NULL DEFAULT false,
    do_not_contact   BOOLEAN      NOT NULL DEFAULT false,
    attempts         SMALLINT     NOT NULL DEFAULT 0,
    last_error       TEXT,
    added_at         TIMESTAMPTZ,
    messaged_at      TIMESTAMPTZ,
    first_reply_at   TIMESTAMPTZ,
    pitched_at       TIMESTAMPTZ,
    last_reply_at    TIMESTAMPTZ,
    last_reply_text  TEXT,
    recontact_on     DATE,                            -- วันที่พนักงานนัดทักใหม่
    notes            TEXT,                            -- โน้ตของพนักงาน
    updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now()
);
-- status: PENDING | INVALID | NOT_FOUND | ADDED | MESSAGED | REPLIED | PITCHED
--         | INTERESTED | DECLINED | CLOSED | NO_REPLY | CUSTOMER | ERROR

-- ประวัติข้อความเข้า/ออก
CREATE TABLE line_messages (
    id           BIGSERIAL    PRIMARY KEY,
    outreach_id  BIGINT       NOT NULL REFERENCES line_outreach(id),
    direction    VARCHAR(3)   NOT NULL,   -- 'in' | 'out'
    sender       VARCHAR(10)  NOT NULL,   -- 'shop' | 'bot' | 'staff'
    text         TEXT,
    source       VARCHAR(20)  NOT NULL,   -- 'notification' | 'chat_scan' | 'chat_read' | 'bot'
    created_at   TIMESTAMPTZ  NOT NULL DEFAULT now()
);

-- เครื่อง/บัญชี LINE ที่บอทใช้
CREATE TABLE line_devices (
    device_id     VARCHAR(64)  PRIMARY KEY,   -- ADB serial
    line_account  VARCHAR(100),
    daily_quota   SMALLINT     NOT NULL DEFAULT 15,
    status        VARCHAR(20)  NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE | PAUSED | RESTRICTED
    paused_until  TIMESTAMPTZ,
    last_seen_at  TIMESTAMPTZ
);
```

## 9. ลำดับการพัฒนา

| Phase | งาน | เกณฑ์ผ่าน |
|---|---|---|
| 0. เตรียม (เจ้าของ) | บัญชี LINE ของพนักงาน + มือถือ Android, ทดลองด้วยมือ, ข้อมูลสำหรับข้อความ (ข้อ 10) | checklist ครบ |
| 1. ฐานข้อมูล + PoC มือถือ | ตารางใน Neon, สคริปต์นำเข้ารอบเดือน, ทักเบอร์ทดสอบ 1 เบอร์ครบ flow | ทักเบอร์ของทีมได้จริง |
| 2. คิว + โควตา | worker รายวัน, เวลาทำงาน, retry, screenshot | รันทั้งวันได้ ไม่ทักซ้ำ |
| 3. ตรวจคำตอบ + ตอบ 1 ครั้ง + แจ้งพนักงาน | notification, สแกนแชท, classifier, B1–B5, Telegram | ตอบถูกกลุ่ม และพนักงานได้แจ้งเตือนภายในไม่กี่นาที |
| 4. Dashboard | รายการร้านที่ตอบ, พนักงานอัปเดตผล/นัดทักใหม่, funnel, เทียบ Q1/Q2 | พนักงานใช้เองได้ |
| 5. เสริม (ถ้าต้องการ) | LINE OA สำหรับร้านที่เป็นลูกค้าแล้ว, AI ช่วยจัดกลุ่มคำตอบ, SMS สำหรับร้านที่ค้นไม่เจอ | — |

ทดสอบกับเบอร์ของทีมก่อนทุกเฟส แล้วค่อยใช้กับร้านจริงทีละน้อย

## 10. Checklist Phase 0

- [ ] เลือกบัญชี: บัญชีใหม่ในชื่อพนักงาน (แนะนำ) หรือ LINE ส่วนตัวจริง (ต้องมีความยินยอมของพนักงาน)
- [ ] มือถือเป็น Android (ยี่ห้อ/รุ่น/เวอร์ชัน) และ PC ที่ต่อมือถือเป็น Windows / macOS / Linux
- [ ] ตั้งค่ามือถือ: USB debugging (Xiaomi เปิด *USB debugging (Security settings)* ด้วย), ไม่ล็อกจอ, Stay awake ขณะชาร์จ,
      ปิด battery optimization และ auto-update ของ LINE, เปิดแจ้งเตือน + แสดงตัวอย่างข้อความ, ปิด "เพิ่มเพื่อนอัตโนมัติ"
- [ ] ทดลองด้วยมือกับเบอร์ของทีม 5–10 เบอร์: รูปแบบเบอร์ที่ช่องค้นหารับ, หน้าจอแต่ละกรณี (เก็บ screenshot),
      เปลี่ยนชื่อเพื่อนได้ยาวสุดกี่ตัวอักษร, notification แสดงชื่อที่เราเปลี่ยนหรือไม่
- [ ] ล็อกอิน LINE PC ด้วยบัญชีเดียวกัน แล้วดูว่า notification บนมือถือยังเด้งอยู่ไหม
- [ ] ข้อมูลสำหรับข้อความ: ชื่อพนักงาน, ชื่อโรงงาน, ชนิดลูกชิ้น, ข้อเสนอจริง, พื้นที่และวันส่ง, ขั้นต่ำการสั่ง
- [ ] โครงสร้างตารางร้านค้าใน Neon (ชื่อตาราง + คอลัมน์ ไม่ต้องส่งข้อมูลจริง) และแหล่งที่มาของรายชื่อร้าน
- [ ] สร้างกลุ่ม Telegram สำหรับแจ้งเตือนพนักงาน
