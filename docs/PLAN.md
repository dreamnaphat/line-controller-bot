# แผนพัฒนา LINE Controller Bot

> สถานะ: แผนงานเบื้องต้น (ยังไม่เริ่มเขียนโค้ด)

## 1. เป้าหมายระยะแรก

1. ดึงเบอร์โทรลูกค้าจากฐานข้อมูล → ค้นหาใน LINE ด้วยเบอร์ → เพิ่มเพื่อน → ส่งข้อความทักทาย
2. ติดตามได้ว่าลูกค้าแต่ละคนที่ทักไปแล้ว **ตอบกลับหรือยัง** (ดูพร้อมกันได้หลายคน)

นอกขอบเขตตอนนี้: ตอบกลับอัตโนมัติ, แชทบอท, บรอดแคสต์

## 2. ข้อจำกัดที่ต้องรู้ก่อนเริ่ม

| เรื่อง | รายละเอียด | ผลต่อการออกแบบ |
|---|---|---|
| ลูกค้าต้องเปิด "ให้ผู้อื่นเพิ่มเพื่อน" | การค้นหาด้วยเบอร์จะเจอเฉพาะคนที่เปิดการตั้งค่านี้ไว้ | ต้องมีสถานะ `NOT_FOUND` และช่องทางสำรอง (SMS/โทร) |
| LINE จำกัดการค้นหา | ถ้าค้นหาเกินจำนวนที่กำหนด หรือค้นเบอร์ที่ไม่พบติดกันหลายครั้ง ฟีเจอร์ค้นหาจะถูกระงับชั่วคราว (LINE ไม่เปิดเผยตัวเลขและระยะเวลา) | โควตาต่อวัน, คัดเบอร์ที่ไม่ใช่มือถือทิ้งก่อนค้น, พักเครื่องเมื่อเจอ "ไม่พบ" ติดกัน, หยุดทันทีเมื่อเจอข้อความเตือน |
| เพื่อนสูงสุด 5,000 คนต่อบัญชี | นับรวมคนที่ซ่อนและบล็อก | ถ้าลูกค้าเกินหลักพัน ต้องวางแผนหลายบัญชีหรือใช้ LINE OA |
| เงื่อนไขการใช้งาน LINE | บัญชีส่วนตัวไม่ได้มีไว้สำหรับทักลูกค้าจำนวนมาก (LINE แนะนำให้ใช้ LINE Official Account) และการควบคุมแอปด้วยโปรแกรมไม่ใช่ช่องทางที่ LINE รองรับ → เสี่ยงถูกจำกัดหรือระงับบัญชี | ใช้บัญชี LINE แยกสำหรับงานนี้ ไม่ใช้บัญชีส่วนตัวหลัก, ปริมาณต่ำ, ข้อความสุภาพและระบุตัวตนชัด |
| PDPA | เบอร์โทรเป็นข้อมูลส่วนบุคคล การใช้ติดต่อเชิงการตลาดควรมีฐานทางกฎหมาย (เช่น ความยินยอม) | ข้อความแรกบอกว่าเป็นใคร/ติดต่อเรื่องอะไร + วิธีปฏิเสธ, เก็บรายชื่อห้ามติดต่อ |
| UI ของ LINE เปลี่ยนตามเวอร์ชัน | บอทที่อิงหน้าจอพังได้เมื่อ LINE อัปเดต | ปิด auto-update ของ LINE, เก็บ selector ไว้ในไฟล์ config, เก็บ screenshot ทุกครั้งที่ error |

## 3. แนวทางที่เลือก

### A. ควบคุมแอป LINE บนมือถือ Android (แนวทางหลักของโปรเจกต์นี้)

- ✅ เพิ่มเพื่อนจากเบอร์ได้ทันที ลูกค้าไม่ต้องทำอะไร, ต้นทุนต่ำ
- ⚠️ เสี่ยงบัญชีถูกจำกัด/แบน, ปริมาณต่อวันต่ำ, ต้องดูแลเมื่อ LINE อัปเดต
- เหมาะกับปริมาณหลักสิบรายต่อวัน

### B. LINE Official Account + Messaging API (ทางการ — เก็บไว้เป็นทางขยาย)

- ส่ง SMS ลิงก์เฉพาะบุคคลให้ลูกค้ากดเพิ่มเพื่อน OA (ผ่านหน้า LIFF เพื่อผูก LINE userId กับรหัสลูกค้าโดยอัตโนมัติ)
- ข้อความตอบกลับเข้ามาทาง webhook → ติดตามได้แม่นยำแบบ real-time, แอดมินหลายคนตอบได้พร้อมกัน, ไม่มีเพดาน 5,000 เพื่อน
- **LINE Official Notification** (มีในไทย) ส่งถึงเบอร์โทรได้โดยไม่ต้องเป็นเพื่อน แต่ใช้ได้เฉพาะข้อความแจ้งเตือน/ธุรกรรม ห้ามการตลาด, ต้องใช้ผ่าน partner ของ LINE และลูกค้าต้องยืนยันยอมรับในครั้งแรก
- ❌ ลูกค้าต้องกดเพิ่มเพื่อนเอง (อัตราตอบรับต่ำกว่า), มีค่า SMS และค่าแพ็กเกจข้อความ

### ข้อสรุป

ทำแนวทาง A ก่อนตามความต้องการ แต่ **แยกชั้นการติดตามสถานะออกจากช่องทางส่ง** (คอลัมน์ `channel` ในฐานข้อมูล)
เพื่อให้เพิ่มแนวทาง B ภายหลังได้โดยใช้ฐานข้อมูลและ dashboard เดิม

## 4. สถาปัตยกรรม

```text
[Customer DB] <--> [Bot Server (Python)] <-- USB / ADB (uiautomator2) --> [Android + LINE]
                     ├─ Scheduler / Queue    quota, working hours, retry
                     ├─ Device Worker        search -> add -> rename -> send
                     ├─ Reply Tracker        notifications + chat-list scan
                     ├─ Alerts               Telegram / Discord / Email
                     └─ Dashboard (web)      status per customer, CSV export
```

### เครื่องมือ

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| ภาษา | Python 3.11+ | ไลบรารีควบคุม Android และจัดการข้อมูลครบ |
| ควบคุมมือถือ | [uiautomator2](https://github.com/openatx/uiautomator2) (ทำงานบน ADB) | หาปุ่มจาก resource-id/ข้อความแทนการกดตามพิกัด, ใส่ข้อความภาษาไทยได้, มี watcher ปิด popup อัตโนมัติ |
| หา selector | uiautodev | ดูโครงสร้างหน้าจอ LINE เพื่อหา id ของปุ่ม/ช่องกรอก |
| ดูหน้าจอสด | scrcpy | เฝ้าดู/ควบคุมมือถือจาก PC |
| ฐานข้อมูล | DB เดิม + ตารางใหม่ (ผ่าน SQLAlchemy) | ไม่ต้องย้ายข้อมูลลูกค้า |
| Dashboard | Streamlit (เร็วสุด) หรือ FastAPI | ดูสถานะ/ส่งออก CSV |
| แจ้งเตือนผู้ดูแล | Telegram / Discord / อีเมล | LINE Notify ปิดบริการไปแล้วเมื่อ 31 มี.ค. 2025 |

> ⚠️ ห้ามใช้ `adb shell input text` ส่งข้อความ เพราะพิมพ์ภาษาไทยไม่ได้ ให้ใช้ `set_text()` ของ uiautomator2 (สำรอง: ADBKeyBoard)

### อุปกรณ์และการตั้งค่า

- **มือถือ Android เครื่องจริง** (ไม่แนะนำ emulator และ iPhone — iOS ต้องใช้ Mac + WebDriverAgent ยุ่งยากกว่ามาก)
- **บัญชี LINE แยกสำหรับงานนี้** + ซิมของบัญชีนั้น (1 บัญชี LINE ใช้บนมือถือได้ครั้งละ 1 เครื่อง → 1 เครื่อง = 1 บัญชี)
- **PC หรือ mini PC** เปิดทิ้งไว้ ต่อสาย USB (เสถียรกว่า ADB ผ่าน Wi-Fi)
- ตั้งค่ามือถือ: เปิด Developer options → USB debugging (Xiaomi ต้องเปิด *USB debugging (Security settings)* เพิ่ม),
  ปิดล็อกหน้าจอ, เปิด Stay awake ขณะชาร์จ, ปิด battery optimization ของ LINE
- ตั้งค่า LINE:
  - ปิด auto-update ของ LINE ใน Play Store และจดเวอร์ชันที่ใช้
  - ล็อกภาษาแอป (ไทยหรืออังกฤษ) — selector ที่อิงข้อความขึ้นกับภาษา
  - เปิดการแจ้งเตือน + **แสดงตัวอย่างข้อความ** (ใช้ติดตามคำตอบ)
  - ปิด "เพิ่มเพื่อนอัตโนมัติ" กันรายชื่อในสมุดโทรศัพท์ปนเข้ามา
  - ตั้งชื่อ/รูปโปรไฟล์เป็นชื่อร้าน/บริษัท ให้ลูกค้าจำได้และไม่กดรายงาน

## 5. การทำงานของบอท

### 5.1 เตรียมข้อมูล

1. ดึงลูกค้าที่ยังไม่อยู่ในตาราง `line_outreach`
2. Normalize เบอร์: ตัด `-` และช่องว่าง, แปลง `+66`/`66` นำหน้าเป็น `0`
3. ตรวจว่าเป็นเบอร์มือถือไทย 10 หลัก (`06`, `08`, `09`) — ไม่ผ่านให้เป็น `INVALID` โดยไม่เสียโควตาค้นหา
4. ตัดเบอร์ซ้ำ และเบอร์ในรายชื่อห้ามติดต่อ
5. สร้าง tag สั้น ๆ ต่อคน เช่น `C1023` (จากรหัสลูกค้า)

### 5.2 เพิ่มเพื่อน + ทัก (ต่อ 1 ราย)

1. กลับหน้า Home ของ LINE (reset ทุกครั้งก่อนเริ่มรายใหม่)
2. เพิ่มเพื่อน → ค้นหา → เลือก "หมายเลขโทรศัพท์" → ใส่เบอร์ → ค้นหา
3. อ่านผลลัพธ์:
   - พบ + ปุ่ม "เพิ่ม" → กดเพิ่ม → `ADDED`
   - พบ + ปุ่ม "แชท" (เป็นเพื่อนอยู่แล้ว) → `ADDED` (บันทึกหมายเหตุว่าเป็นเพื่อนอยู่ก่อน)
   - ไม่พบผู้ใช้ → `NOT_FOUND`
   - ข้อความแจ้งจำกัดการค้นหา → `RATE_LIMITED` → พักเครื่องนี้ถึงวันถัดไป + แจ้งเตือน
4. **เปลี่ยนชื่อที่แสดงของเพื่อน** (เห็นเฉพาะฝั่งเรา) เป็น `C1023 สมชาย` — ตั้งให้สั้น เพราะชื่อที่แสดงใน LINE จำกัดความยาว (ราว 20 ตัวอักษร)
   → หัวใจของการติดตาม: รายการแชทและ notification จะมีรหัสลูกค้าติดมาเสมอ แม้ลูกค้าเปลี่ยนชื่อโปรไฟล์
5. เข้าแชท → ใส่ข้อความจาก template (แทนชื่อลูกค้า) → กดส่ง
6. ตรวจว่าข้อความขึ้นในห้องแชทจริง → `MESSAGED` + เวลา
7. บันทึกลง DB ทันทีหลังแต่ละขั้น — ถ้าบอทล่มกลางทาง รอบหน้าทำต่อได้โดยไม่ทักซ้ำ
8. เว้นระยะแบบสุ่มก่อนรายถัดไป (เช่น 1–3 นาที)

> ทางเลือกที่ไม่ใช้: นำเบอร์เข้าสมุดโทรศัพท์แล้วให้ LINE "เพิ่มเพื่อนอัตโนมัติ" — เร็วกว่า
> แต่ระบุไม่ได้แน่ชัดว่าเพื่อนคนไหนตรงกับเบอร์ไหน จึงติดตามรายคนไม่ได้

### 5.3 สถานะของลูกค้าแต่ละราย

```text
PENDING ──► INVALID                      (เบอร์ไม่ใช่มือถือ ตัดทิ้งก่อนค้นหา)
   │
   ▼
SEARCHING ──► NOT_FOUND                  (ไม่มี LINE หรือปิดการค้นหาด้วยเบอร์)
   │     └──► RATE_LIMITED ──► PENDING   (พักเครื่อง ลองใหม่วันถัดไป)
   ▼
ADDED ──► MESSAGED ──► REPLIED
                  └──► NO_REPLY          (ไม่ตอบเกิน N วัน -> ลิสต์ให้ทีมขาย follow-up)
```

ขั้นใดล้มเหลว → `ERROR` (attempts + 1, เก็บ screenshot + UI dump) → ลองใหม่สูงสุด 3 ครั้ง

### 5.4 ติดตามการตอบกลับ (3 ชั้น)

| ชั้น | วิธี | ความถี่ | ข้อดี / ข้อจำกัด |
|---|---|---|---|
| 1. Notification | อ่านการแจ้งเตือนของแอป LINE (ชื่อผู้ส่ง + ข้อความ) แล้วจับคู่ tag | real-time | เร็ว ไม่ต้องแย่งหน้าจอกับงานทัก / ถ้า LINE เปิดอยู่บนหน้าจอ notification อาจไม่เด้ง, หลายข้อความอาจถูกรวมกัน |
| 2. สแกนรายการแชท | เปิดแท็บแชท เลื่อนอ่านทุกแถว (ชื่อ, ข้อความล่าสุด, จำนวนที่ยังไม่อ่าน) **โดยไม่กดเข้าห้อง** | ทุก 15–30 นาที ช่วงว่างงาน | เก็บตกสิ่งที่ชั้น 1 พลาด / ตัวเลขยังไม่อ่านจะหายถ้ามีคนเปิดอ่านไปแล้ว (รวมถึงจาก LINE PC) |
| 3. เปิดห้องแชท (ไม่บังคับ) | ดูว่ามีข้อความฝั่งลูกค้า (bubble ซ้าย) หลังข้อความของเราหรือไม่ | เฉพาะรายที่ไม่ชัดเจน | แม่นที่สุด / ลูกค้าจะเห็นว่า "อ่านแล้ว" |

วิธีอ่าน notification (เลือกอย่างใดอย่างหนึ่ง):

- **ก. ผ่าน ADB จาก PC** — ดึง `adb shell dumpsys notification --noredact` ทุก ~10 วินาที แล้วกรองแพ็กเกจ `jp.naver.line.android`
  ไม่ต้องลงแอปเพิ่ม แต่ต้อง parse ข้อความที่รูปแบบต่างกันตามเวอร์ชัน Android
- **ข. แอปบนมือถือส่งต่อเข้า webhook ของบอท** — MacroDroid (ไม่ต้องเขียนโค้ด) หรือเขียนแอป Android เล็ก ๆ
  ที่ใช้ `NotificationListenerService` ซึ่งเสถียรกว่า

ทุกคำตอบที่จับได้ → บันทึกลง `line_messages` (direction = `in`) และอัปเดต `REPLIED`, `first_reply_at`, `last_reply_text`

### 5.5 Dashboard

- ตารางลูกค้า + ตัวกรองสถานะ: รอตอบ / ตอบแล้ว (ข้อความล่าสุด + เวลา) / ไม่พบ LINE / ไม่ตอบเกิน N วัน
- ตัวเลขสรุปรายวัน: ค้นหา, เพิ่มสำเร็จ, ส่งแล้ว, ตอบแล้ว, % การตอบ
- ส่งออก CSV ให้ทีมขาย follow-up
- สถานะเครื่อง: ออนไลน์ / พัก / ถูกจำกัด, โควตาที่ใช้วันนี้

### 5.6 การจัดคิวและความปลอดภัยของบัญชี

- 1 เครื่อง = 1 worker (หน้าจอใช้ได้ทีละงาน) สลับระหว่าง "ทักรายใหม่" กับ "สแกนแชท"; การอ่าน notification ทำคู่ขนานได้
- โควตาต่อวันต่อเครื่อง เริ่มต่ำ (เช่น 10–20 รายต่อวัน) แล้วค่อยปรับจากผลจริง
- ทำงานเฉพาะเวลาที่เหมาะสม (เช่น 9:00–19:00)
- พักเครื่องอัตโนมัติเมื่อเจอ "ไม่พบ" ติดกันหลายครั้ง, หยุดทันทีและแจ้งเตือนเมื่อพบ popup เตือน/จำกัด หรือ error ติดกัน
- ข้อความแรก: ชื่อร้าน/บริษัท + เหตุผลที่ติดต่อ + วิธีปฏิเสธ (เช่น พิมพ์ "ไม่สนใจ") → ลดการกดรายงาน
- ลูกค้าที่ปฏิเสธ → เข้ารายชื่อห้ามติดต่อ

### 5.7 ความทนทานของบอท

- selector ทั้งหมดอยู่ใน `config/selectors.yaml` — LINE เปลี่ยน UI แก้ที่เดียว
- ลำดับการหา element: resource-id → ข้อความ/คำอธิบาย → (สำรอง) รูปภาพ/OCR
- ทุก error เก็บ screenshot + UI dump + log
- watcher ปิด popup ที่ไม่คาดคิด (อัปเดตแอป, โปรโมชัน, ขอสิทธิ์)
- recovery: กด Back จนถึง Home → ถ้าไม่ได้ force-stop แล้วเปิด LINE ใหม่
- health check ก่อนเริ่มงาน: ADB เชื่อมต่อ, จอติด/ปลดล็อก, LINE ล็อกอินอยู่, แบตเตอรี่พอ

## 6. ฐานข้อมูล (ตารางใหม่)

ตัวอย่างเขียนแบบ PostgreSQL — ปรับตาม DB ที่ใช้จริง

```sql
-- สถานะการทักลูกค้าแต่ละราย
CREATE TABLE line_outreach (
    id               BIGSERIAL PRIMARY KEY,
    customer_id      BIGINT       NOT NULL,              -- FK ไปตารางลูกค้าเดิม
    phone            VARCHAR(15)  NOT NULL,              -- normalize แล้ว เช่น 0812345678
    channel          VARCHAR(20)  NOT NULL DEFAULT 'line_app',  -- เผื่อ 'line_oa'
    device_id        VARCHAR(64),                        -- ADB serial ของเครื่องที่ทัก
    tag              VARCHAR(12)  UNIQUE,                -- เช่น C1023
    line_name        VARCHAR(100),                       -- ชื่อโปรไฟล์ LINE ตอนค้นเจอ
    status           VARCHAR(20)  NOT NULL DEFAULT 'PENDING',
    attempts         INT          NOT NULL DEFAULT 0,
    last_error       TEXT,
    added_at         TIMESTAMPTZ,
    messaged_at      TIMESTAMPTZ,
    first_reply_at   TIMESTAMPTZ,
    last_reply_at    TIMESTAMPTZ,
    last_reply_text  TEXT,
    updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (customer_id, channel)                        -- กันทักซ้ำ
);

-- ประวัติข้อความเข้า/ออก
CREATE TABLE line_messages (
    id           BIGSERIAL PRIMARY KEY,
    outreach_id  BIGINT      NOT NULL REFERENCES line_outreach(id),
    direction    VARCHAR(3)  NOT NULL,         -- 'out' | 'in'
    text         TEXT,
    source       VARCHAR(20) NOT NULL,         -- 'bot' | 'notification' | 'chat_scan'
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- เครื่อง/บัญชี LINE
CREATE TABLE line_devices (
    device_id     VARCHAR(64) PRIMARY KEY,     -- ADB serial
    line_account  VARCHAR(100),
    daily_quota   INT         NOT NULL DEFAULT 15,
    status        VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE | PAUSED | RESTRICTED
    paused_until  TIMESTAMPTZ,
    last_seen_at  TIMESTAMPTZ
);
```

## 8. ลำดับการพัฒนา

| Phase | งาน | เกณฑ์ผ่าน |
|---|---|---|
| 0. ทดสอบด้วยมือ | ตั้งค่ามือถือ + บัญชี LINE, ลองค้นหา/เพิ่ม/ทักด้วยมือ 5–10 เบอร์ของทีมเอง | ตอบรายการตรวจในหัวข้อ 9 ได้ครบ |
| 1. PoC | สคริปต์ uiautomator2: เบอร์ 1 เบอร์ → เพิ่ม → เปลี่ยนชื่อ → ส่งข้อความ | รันครบ flow กับเบอร์ทดสอบ |
| 2. DB + คิว | ตาราง outreach, state machine, retry, screenshot เมื่อ error, โควตา/เวลาทำงาน | รันทั้งวันได้ ไม่ทักซ้ำ ล่มแล้วทำต่อได้ |
| 3. ติดตามการตอบ | notification listener + สแกนรายการแชท | ลูกค้าตอบ → เป็น `REPLIED` ภายในไม่กี่นาที |
| 4. Dashboard + แจ้งเตือน | หน้าเว็บสถานะ, export CSV, แจ้งเตือนเมื่อเครื่องมีปัญหา | ทีมขายใช้งานเองได้ |
| 5. ขยาย (ถ้าจำเป็น) | หลายเครื่อง/หลายบัญชี หรือเพิ่มช่องทาง LINE OA | — |

ใช้เบอร์ของทีมเองทดสอบตลอด Phase 1–3 ก่อนใช้กับลูกค้าจริง แล้วค่อย ๆ เพิ่มปริมาณ

## 9. รายการตรวจใน Phase 0

- [ ] ช่องค้นหารับเบอร์รูปแบบไหน (`0812345678` / ไม่มี 0 นำหน้า / ต้องเลือกรหัสประเทศ)
- [ ] หน้าตาผลลัพธ์ทุกกรณี: พบ / เป็นเพื่อนแล้ว / ไม่พบ / ถูกจำกัดการค้นหา (เก็บ screenshot ไว้)
- [ ] เปลี่ยนชื่อเพื่อนได้ยาวสุดกี่ตัวอักษร
- [ ] notification แสดง "ชื่อที่เราเปลี่ยน" หรือ "ชื่อโปรไฟล์ของลูกค้า"
- [ ] หน้าจอ LINE เวอร์ชันนี้มี resource-id ให้จับหรือไม่ (ตรวจด้วย uiautodev)
- [ ] ถ้าล็อกอิน LINE PC ด้วย notification บนมือถือยังเด้งอยู่ไหม และสถานะอ่านแล้ว sync กันอย่างไร

## 10. ข้อมูลที่ต้องการจากเจ้าของโปรเจกต์

1. จำนวนลูกค้าทั้งหมด และอยากทักวันละกี่ราย
2. ฐานข้อมูลเป็นระบบอะไร (MySQL / PostgreSQL / SQL Server / Google Sheets / Excel) และตารางลูกค้ามีคอลัมน์อะไร
3. มีมือถือ Android + บัญชี LINE แยกสำหรับงานนี้ไหม และเครื่องที่จะรันบอทเป็น Windows / macOS / Linux
4. ข้อความแรกที่ต้องการส่ง และลูกค้าเคยยินยอมให้ติดต่อทาง LINE หรือไม่
5. เมื่อลูกค้าตอบแล้ว ใครคุยต่อ และคุยจากที่ไหน (มือถือเครื่องเดียวกัน / LINE PC / ผ่าน dashboard ในเฟสถัดไป)
