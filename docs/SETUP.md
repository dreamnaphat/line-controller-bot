# คู่มือติดตั้งและทดลอง (Phase 0–1)

ใช้กับมือถือ **Honor 400 Pro** และคอมพิวเตอร์ **Windows** (ภายหลังย้ายไป **MacBook** ได้ด้วยขั้นตอนเดียวกัน)

## 1. สิ่งที่ต้องมี

- มือถือ Android (Honor 400 Pro) + สาย USB ที่ **รับส่งข้อมูลได้** (สายชาร์จอย่างเดียวใช้ไม่ได้)
- บัญชี LINE ใหม่สำหรับงานนี้ ตั้งชื่อแยก (ไม่ใช้ชื่อจริงพนักงาน) ล็อกอินไว้บนมือถือเครื่องนี้
- เบอร์ของทีมที่มี LINE 2–3 เบอร์ ไว้ทดสอบ (ห้ามทดสอบกับร้านจริง)
- connection string ของ Neon

## 2. ตั้งค่ามือถือ Honor 400 Pro

ชื่อเมนูอาจต่างกันเล็กน้อยตามเวอร์ชัน MagicOS

1. **เปิดตัวเลือกสำหรับนักพัฒนา**: การตั้งค่า → เกี่ยวกับโทรศัพท์ → แตะ "หมายเลขรุ่นสร้าง" (Build number) 7 ครั้ง
2. การตั้งค่า → ระบบและการอัปเดต → ตัวเลือกสำหรับนักพัฒนา
   - เปิด **การแก้ไขข้อบกพร่อง USB** (USB debugging)
   - ถ้ามี "อนุญาตการแก้ไขข้อบกพร่อง ADB ในโหมดชาร์จเท่านั้น" ให้เปิดด้วย
   - เปิด **หน้าจอเปิดตลอด** (Stay awake) เพื่อไม่ให้จอดับขณะชาร์จ
3. ตั้งการล็อกหน้าจอเป็น **ไม่มี**
4. แบตเตอรี่ → การเปิดแอป (App launch) → LINE → เปลี่ยนเป็นจัดการเอง และอนุญาตให้ทำงานเบื้องหลัง
5. Play Store → LINE → เมนู ⋮ → ปิด **อัปเดตอัตโนมัติ** (LINE อัปเดตแล้วหน้าจอเปลี่ยน บอทอาจหาปุ่มไม่เจอ)
6. ในแอป LINE:
   - การตั้งค่า → การแจ้งเตือน → เปิดการแจ้งเตือน และเปิด **แสดงตัวอย่างข้อความ**
   - การตั้งค่า → เพื่อน → ปิด **เพิ่มเพื่อนอัตโนมัติ**
   - ใช้ภาษาไทยไว้ตลอด (selector บางตัวอิงข้อความภาษาไทย)

## 3. ติดตั้งโปรแกรมบนคอมพิวเตอร์

### Windows

1. ติดตั้ง Python 3.11 ขึ้นไปจาก <https://www.python.org/downloads/> — ตอนติดตั้งติ๊ก **Add python.exe to PATH**
2. ติดตั้ง Git จาก <https://git-scm.com/download/win> (หรือดาวน์โหลดโปรเจกต์เป็น ZIP จาก GitHub)
3. (แนะนำ) เปิด PowerShell แล้วติดตั้งเครื่องมือเสริม:
   ```powershell
   winget install Google.PlatformTools   # คำสั่ง adb
   winget install Genymobile.scrcpy      # ดูหน้าจอมือถือบนคอมพิวเตอร์
   ```
4. ถ้าต่อสายแล้วคอมพิวเตอร์มองไม่เห็นมือถือ: เปลี่ยนสาย, ตั้งโหมด USB บนมือถือเป็น "ถ่ายโอนไฟล์",
   หรือติดตั้งไดรเวอร์ USB ของ Honor (มากับโปรแกรมจัดการมือถือของ Honor สำหรับ PC)

### macOS (MacBook ภายหลัง)

```bash
brew install python@3.12 scrcpy
brew install --cask android-platform-tools
```

ไม่ต้องติดตั้งไดรเวอร์เพิ่ม

## 5. ตั้งฐานข้อมูล (ครั้งเดียว)

1. แนะนำให้สร้าง branch `dev` ใน Neon Console ก่อน แล้วใช้ connection string ของ `dev` ทดสอบ
2. สร้างตารางของบอท (อยู่ใน schema `line_bot` แยกจากตารางเดิม ไม่แตะตาราง `Shop`):
   ```bash
   python -m bot init-db
   ```
   หรือวางไฟล์ `db/schema.sql` ทั้งไฟล์ใน SQL Editor ของ Neon
3. ดึงร้านใหม่เข้าคิว — รันครั้งแรกจะแสดงตัวอย่างเท่านั้น:
   ```bash
   python -m bot import
   python -m bot import --commit    # ถ้าตัวอย่างถูกต้อง
   ```
   ตัวกรองร้าน (status, visited, foodType, อายุร้าน) ตั้งได้ใน `config/settings.yaml` หัวข้อ `import`

## 5.1 โหมดทดสอบ (เปิดไว้เป็นค่าเริ่มต้น)

ระหว่างทดสอบ บอทจะทักได้เฉพาะเบอร์ของทีม แม้คิวจะมีร้านจริงอยู่ก็ตาม

1. ใส่เบอร์ทีมในไฟล์ `.env` คั่นด้วยจุลภาค:
   ```
   TEST_PHONES=0812345678,0898765432
   ```
2. เพิ่มร้านสมมติที่ใช้เบอร์ทีมเข้าคิว (เพิ่มซ้ำได้ ร้านจะถูกรีเซ็ตกลับเป็น PENDING เพื่อทดสอบใหม่):
   ```bash
   python -m bot test-add --phone 0812345678 --name "ร้านทดสอบ 1"
   ```
3. ทดสอบเสร็จแล้วลบร้านสมมติทั้งหมดออกจากคิว:
   ```bash
   python -m bot test-clear
   ```
4. เมื่อพร้อมทักร้านจริง ให้ตั้ง `safety.test_mode: false` ใน `config/settings.yaml`

## 6. ตรวจการเชื่อมต่อมือถือ

1. ต่อสาย USB → บนมือถือจะมีหน้าต่าง "อนุญาตการแก้ไขข้อบกพร่อง USB" → ติ๊ก "อนุญาตจากคอมพิวเตอร์เครื่องนี้เสมอ" → อนุญาต
2. รัน
   ```bash
   python -m bot doctor
   ```
   ครั้งแรกระบบจะติดตั้งแอปช่วยควบคุม (uiautomator) ลงมือถือ ถ้ามีหน้าต่างถามยืนยันบนมือถือให้กดอนุญาต แล้วรันใหม่
   ทุกบรรทัดที่เป็น `[OK]` แปลว่าพร้อม (`[--]` คือไม่บังคับ)

## 7. เก็บข้อมูลหน้าจอ LINE (ทำร่วมกับผู้พัฒนา)

บอทต้องรู้ว่าปุ่มแต่ละปุ่มใน LINE เวอร์ชันบนมือถือเครื่องนี้ชื่ออะไร ให้เปิดแต่ละหน้าบนมือถือด้วยมือ แล้วรันคำสั่งตามตาราง

| หน้าจอที่เปิดไว้ | คำสั่ง |
|---|---|
| หน้าหลัก | `python -m bot dump home` |
| หน้าเพิ่มเพื่อน | `python -m bot dump add-friend` |
| หน้าค้นหา (เลือก "หมายเลขโทรศัพท์" แล้ว) | `python -m bot dump search-phone` |
| ผลค้นหา: เจอ แต่ยังไม่เป็นเพื่อน (เบอร์ทีม) | `python -m bot dump result-found` |
| ผลค้นหา: เป็นเพื่อนกันแล้ว | `python -m bot dump result-friend` |
| ผลค้นหา: ไม่พบ (เบอร์ที่ไม่มี LINE) | `python -m bot dump result-not-found` |
| หน้าโปรไฟล์เพื่อน (ที่มีไอคอนแก้ชื่อ) | `python -m bot dump profile` |
| หน้าแก้ชื่อเพื่อน | `python -m bot dump rename` |
| ห้องแชท (พิมพ์ข้อความค้างไว้ ยังไม่ส่ง) | `python -m bot dump chat` |

- ไฟล์จะอยู่ในโฟลเดอร์ `dumps/` ส่งเฉพาะไฟล์ `.txt` ให้ผู้พัฒนา (คัดลอกข้อความวางในแชทได้)
- ไฟล์อาจมีชื่อหรือข้อความที่อยู่บนหน้าจอ จึงควรใช้เบอร์ของทีมตอนเก็บ
- **ค้นเบอร์ที่ไม่มี LINE แค่ 1–2 ครั้งพอ** เพราะค้นไม่เจอติดกันหลายครั้ง LINE จะระงับการค้นหาชั่วคราว
- ระหว่างนี้จดด้วยว่า: ช่องค้นหารับเบอร์แบบไหน (`0812345678` หรือต้องตัด 0), เปลี่ยนชื่อเพื่อนได้ยาวสุดกี่ตัวอักษร,
  และตอนเพื่อนทักมา การแจ้งเตือนแสดงชื่อที่เราตั้งให้หรือชื่อโปรไฟล์ของเขา

## 8. ทดลองทักเบอร์ทดสอบ (PoC)

หลังผู้พัฒนาอัปเดต `config/selectors.yaml` จากไฟล์ในข้อ 7 แล้ว:

```bash
python -m bot poc --phone 08xxxxxxxx --step            # ทำทีละขั้น กด Enter เพื่อไปต่อ ยังไม่ส่งข้อความ
python -m bot poc --phone 08xxxxxxxx --rename --send   # ลองเปลี่ยนชื่อเพื่อนและส่งจริง
```

- เปิด `scrcpy` ไว้ดูหน้าจอมือถือบนคอมพิวเตอร์ระหว่างทดสอบ
- ถ้าติดขั้นไหน บอทจะเก็บภาพหน้าจอไว้ในโฟลเดอร์ `logs/` ส่งไฟล์ `.txt` ให้ผู้พัฒนาได้เลย
- ข้อความแรกที่ใช้ตั้งใน `config/settings.yaml` (`opener: Q2`) และแก้ข้อความได้ใน `config/messages.yaml`

## 10. ให้บอททักตามคิว (Phase 2)

ก่อนรันครั้งแรกหลังอัปเดตโค้ด ให้รัน `python -m bot init-db` อีกครั้ง (เพิ่มคอลัมน์ใหม่ให้ตาราง รันซ้ำได้ ไม่ลบข้อมูล)

```bash
python -m bot status                 # ดูว่าคิวมีร้านสถานะไหนกี่ร้าน
python -m bot run --once --now       # ทดลองทำ 1 ร้าน โดยไม่สนช่วงเวลาทักร้าน
python -m bot run                    # ทำงานต่อเนื่อง: ทักเฉพาะ 14:00–16:30 ไม่เกินโควตาต่อวัน
```

**โควตาต่อวัน (`daily_quota: auto`)** — เกลี่ยร้านในคิวให้ทักหมดภายใน 30 วัน (`finish_within_days`) เพราะหาร้านใหม่ทุกเดือน
- โควตาวันนี้ = ร้านที่เหลือในคิว ÷ จำนวนวันที่เหลือในรอบ (นับจากวันที่ `import` ร้านรอบนั้น) ปัดขึ้น
  เช่น นำเข้า 258 ร้าน → 258 ÷ 30 ≈ 9 ร้าน/วัน
- ถ้าวันไหนบอทไม่ได้ทำงาน วันถัด ๆ ไปโควตาจะเพิ่มขึ้นเองเพื่อให้ยังเสร็จทัน
- ไม่เกิน `max_daily_quota` (25 ร้าน/วัน) กันโดน LINE จำกัด — ถ้าร้านเยอะจนชนเพดาน บอทจะบอกว่าต้องใช้กี่วัน
- ดูโควตาวันนี้ได้จาก `python -m bot status` หรือหน้า dashboard / อยากใช้ตัวเลขตายตัวก็ใส่ เช่น `daily_quota: 15`

- แต่ละร้าน บอทจะ ค้นเบอร์ → เพิ่มเพื่อน → เข้าแชท → เปลี่ยนชื่อเป็นรหัสร้าน → ส่งข้อความแรก แล้วบันทึกลง Neon ทุกขั้น
- ถ้าบอทหยุดกลางทาง (ปิดโปรแกรม ไฟดับ มือถือหลุด) รันใหม่ได้เลย บอทจะทำร้านที่ค้างอยู่ก่อน
  และเช็กในห้องแชทก่อนส่ง ถ้าข้อความเคยออกไปแล้วจะไม่ส่งซ้ำ
- โควตานับจากจำนวนเบอร์ที่ค้นในวันนั้น (รวมที่ค้นไม่เจอ) เพราะ LINE จำกัดที่จำนวนการค้นหา
- ค้นไม่เจอติดกัน 5 ร้าน บอทพัก 1 ชั่วโมง / ถ้า LINE จำกัดการค้นหา บอทหยุดและพักมือถือถึงช่วงทักร้านของวันถัดไป
- ทำไม่สำเร็จ 3 ครั้งในร้านเดียว ร้านนั้นจะเป็นสถานะ ERROR / ไม่สำเร็จติดกัน 3 ร้าน บอทจะหยุดให้คนดู
  ภาพหน้าจอตอนที่ไม่สำเร็จอยู่ใน `logs/` และบันทึกการทำงานทั้งหมดอยู่ใน `logs/worker.log`
- กด Ctrl+C เพื่อหยุดบอทได้ทุกเมื่อ
- ตั้งค่าโควตา ช่วงเวลา และระยะห่างระหว่างร้านได้ใน `config/settings.yaml` หัวข้อ `outreach`
- **โหมดทดสอบ:** บอททักเฉพาะร้านที่ใช้เบอร์ใน `TEST_PHONES` (เพิ่มด้วย `test-add`) ร้านจริงในคิวไม่ถูกแตะ

## 11. ตรวจคำตอบและตอบกลับ (Phase 3)

`python -m bot run` คอยดูคำตอบของร้านไปพร้อมกับการทักร้านใหม่ และยังทำงานต่อหลังคิวหมด (กด Ctrl+C เพื่อหยุด)

1. **อ่านการแจ้งเตือน** ทุก ~30 วินาที (ไม่แตะหน้าจอ) — ต้องเปิดการแจ้งเตือนของ LINE และ "แสดงตัวอย่างข้อความ"
   บอทอ่านเฉพาะแชทที่ชื่อขึ้นต้นด้วยรหัสร้าน เช่น `C12` แชทอื่นไม่ถูกเก็บ
2. **ไล่ดูหน้ารายการแชท** ทุก 20 นาที (`chat_scan_minutes`) เก็บคำตอบที่การแจ้งเตือนพลาด เช่น ตอนบอทกำลังใช้ LINE อยู่
3. หลังใช้ LINE เสร็จ บอทกดกลับหน้าโฮมของมือถือ ข้อความใหม่จะได้เด้งเป็นการแจ้งเตือน
4. ร้านที่ไม่ตอบเกิน 7 วัน (`no_reply_days`) เปลี่ยนเป็น NO_REPLY

**เมื่อร้านตอบ**
- `auto_pitch: false` (ค่าตอนนี้): บอทบันทึกและจัดกลุ่มคำตอบ แล้วแจ้งพนักงานทุกครั้ง ไม่ตอบเอง
- `auto_pitch: true`: บอทตอบ 1 ครั้งตามกลุ่มคำตอบ (B1–B6 ใน `config/messages.yaml`) ทำเฉพาะช่วง `reply_hours`
  หลังจากนั้นข้อความใหม่จะแจ้งพนักงาน ยกเว้นร้านปฏิเสธ บอทปิดบทสนทนาให้อย่างสุภาพ
  ต้องใส่ชื่อโรงงานใน `business.factory_name` และแก้ข้อเสนอใน B1/B2 ให้ตรงของจริงก่อน

```bash
python -m bot check-replies   # ตรวจคำตอบตอนนี้เลย 1 รอบ (ไม่สนเวลา)
python -m bot replies         # รายชื่อร้านที่ตอบแล้วและรอพนักงานคุยต่อ
```

**แจ้งเตือนเข้า Telegram (ไม่บังคับ)**
1. ใน Telegram คุยกับ @BotFather → `/newbot` → ได้ token
2. สร้างกลุ่มของทีม แล้วเพิ่มบอทเข้ากลุ่ม พิมพ์ข้อความอะไรก็ได้ในกลุ่ม 1 ครั้ง
3. เปิด `https://api.telegram.org/bot<token>/getUpdates` ในเบราว์เซอร์ หา `"chat":{"id":-100...}` นั่นคือ chat id
4. ใส่ใน `.env`: `TELEGRAM_BOT_TOKEN=...` และ `TELEGRAM_CHAT_ID=...`

## 12. Dashboard สำหรับพนักงาน (Phase 4)

ติดตั้งไลบรารีเพิ่ม (ครั้งเดียวหลัง `git pull`): `pip install -r requirements.txt`

```bash
python -m bot dashboard          # เปิดในเบราว์เซอร์ที่ http://localhost:8501 (กด Ctrl+C เพื่อปิด)
python -m bot dashboard --lan    # ให้เครื่องอื่นในวง Wi-Fi เดียวกันเปิดได้ (ต้องตั้ง DASHBOARD_PASSWORD ใน .env)
```

รันคู่กับ `python -m bot run` ได้ (เปิดอีกหน้าต่าง PowerShell/Terminal) — dashboard ไม่แตะมือถือ อ่านและเขียนแค่ใน Neon

| แท็บ | ใช้ทำอะไร |
|---|---|
| 💬 รอพนักงาน | ร้านที่ตอบกลับมา: ดูข้อความที่คุยกัน → ไปตอบใน LINE PC (ค้นแชทด้วยรหัส เช่น `C12`) → กลับมาบันทึกผล |
| 📅 นัดทักใหม่ | ร้านที่นัดไว้ (เช่น ยังไม่เปิดร้าน) เรียงตามวัน 🔔 = ถึงวันแล้ว |
| 📊 ภาพรวม | ตัวเลขรวม, โควตาวันนี้, funnel ต่อรอบนำเข้า (นำเข้า → ค้นเจอ → ทัก → ตอบ → สนใจ → ลูกค้า), กราฟ 30 วัน |
| 🔎 ร้านทั้งหมด | ค้นหาร้านด้วยรหัส ชื่อ หรือเบอร์ กรองตามสถานะ แล้วเปิดบันทึกผลได้ |

ผลที่บันทึกได้: ยังคุยอยู่ / สนใจ / เป็นลูกค้าแล้ว / ยังไม่เปิดร้าน (ต้องใส่วันนัดทักใหม่) / ไม่สนใจ / ปิดกิจการ
— "ไม่สนใจ" และ "ปิดกิจการ" ตั้งห้ามทักร้านนี้อีกให้อัตโนมัติ

- ข้อความที่พนักงานพิมพ์ใน LINE PC จะไม่ขึ้นใน dashboard (บอทเก็บเฉพาะข้อความของร้านและของบอท) ให้จดสรุปไว้ในช่องโน้ต
- สวิตช์ "แสดงร้านทดสอบ" ด้านซ้ายใช้ซ่อน/แสดงร้านที่เพิ่มด้วย `test-add`
